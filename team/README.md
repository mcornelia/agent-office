## Onboard an existing task

1. Confirm its stable identity and current workload. Record its assigned guide
   in the private roster as `instructionsFile`, relative to this repository.
   Do not put real task IDs in these public documents.
2. At a safe idle boundary, send one explicit onboarding message naming its
   absolute guide path. Ask it to read that guide and the shared agreements,
   preserve existing work and waits, report any conflict, and acknowledge its
   responsibilities and limits. Do not tell it to restart old work.
3. Preserve settings and record the acknowledgment. For the task carrying out
   onboarding, read its own guide directly; never send a message to itself.

`AGENTS.md` discovery is directory-based, not name-based. These nested guides do
not automatically attach to existing tasks in a shared parent directory. Use
the explicit onboarding reference and a narrowly scoped workspace router for
already-enrolled members; never guess a role from a title or load all six guides.
The private roster maps identities to guide paths; the viewer and local gate do
not load role instructions from that field. Keep the normal task working directory.

Onboarding adds standing guidance, not another monitor, new tasks, model changes,
publication permission, or approval to change existing automations. A fresh-run
loading test is not a substitute for acknowledgment from the actual member.
